# Hero visual directions

These directions are intentionally static, restrained and grounded in the Agila capability ontology. None places AI at the centre of every engagement, and none implies a rigid delivery sequence.

## A. Six-field capability landscape

Shape: a balanced two-by-three field of rectangular panels.

```text
┌───────────────────────┬───────────────────────┬───────────────────────┐
│ Data, analytics       │ Business and          │ Enterprise, solution  │
│ and AI                │ operating-model       │ and integration       │
│                       │ transformation        │ architecture          │
├───────────────────────┼───────────────────────┼───────────────────────┤
│ Industrial operations │ Digital products and  │ Governance, delivery  │
│ IT/OT and IIoT        │ operating systems     │ and adoption          │
└───────────────────────┴───────────────────────┴───────────────────────┘
```

What it communicates: Agila combines six peer capabilities; no single technology or discipline is presented as the centre of the practice.

Best quality: clearest and most faithful representation of the public capability model.

Trade-off: it repeats information that appears in the capability cards further down the page.

## B. Layered transformation system

Shape: four horizontal system layers with one vertical assurance rail.

```text
                                      ┌──────────────────────────┐
┌───────────────────────────────────┐ │ Governance, delivery and │
│ Business and operating-model      │ │ adoption                 │
│ transformation                    │ │                          │
├──────────────────┬────────────────┤ │                          │
│ Data, analytics  │ Digital        │ │                          │
│ and AI           │ products       │ │                          │
├──────────────────┴────────────────┤ │                          │
│ Enterprise, solution and          │ │                          │
│ integration architecture          │ │                          │
├───────────────────────────────────┤ │                          │
│ Industrial operations, IT/OT      │ │                          │
│ and IIoT                          │ │                          │
└───────────────────────────────────┘ └──────────────────────────┘
```

What it communicates: business change sits on connected data, applications, integration and operational foundations, while governance and adoption run across the whole system.

Best quality: explains why isolated AI initiatives underperform without reverting to a generic technology stack.

Trade-off: the vertical order can be read as a hierarchy even though real engagements do not always follow it.

## C. Three engagement lenses

Shape: three vertical columns on a shared, non-sequential foundation.

```text
┌────────────────────────┬────────────────────────┬────────────────────────┐
│ ORGANISE               │ CONNECT                │ APPLY                  │
│                        │                        │                        │
│ Business and operating │ Enterprise, solution  │ Data, analytics and AI │
│ model transformation   │ and integration       │                        │
│                        │                        │ Digital products and   │
│                        │ Industrial operations │ operating systems      │
│                        │ IT/OT and IIoT         │                        │
└────────────────────────┴────────────────────────┴────────────────────────┘
┌──────────────────────────────────────────────────────────────────────────┐
│ Governance, delivery and adoption                                      │
└──────────────────────────────────────────────────────────────────────────┘
```

What it communicates: Agila can enter through a business, systems or applied-technology need while retaining one governed delivery foundation.

Best quality: gives prospective clients three intuitive ways to recognise their own challenge.

Trade-off: the client-friendly grouping is less exact than showing all six capability families as peers.

## Recommendation

Option C is the strongest hero direction because it helps a visitor self-identify without duplicating the detailed capability grid. Option A is the safest if ontology fidelity is the only criterion. Option B is the strongest systems explanation, but needs careful wording to avoid suggesting a universal hierarchy.
